# Set up a V1.0-T wall controller

[Choose another revision](../../README.md#identify-your-wall-controller) ·
[V1 protocol specification](../specs/protocols/v1/protocol.md)

<img src="../assets/v1.0-t.png" width="320" alt="V1.0-T marking on the rear of the wall controller">

Identify the printed **Zone Switch V1.0-T** marking. Software query/toggle control
has been demonstrated on this revision. External queries and writes can leave
wall LEDs stale and temporarily impair physical buttons; repeated presses or a
panel restart have recovered it. This remains experimental even when HA state
updates correctly. Listen-only mode sends no queries, including at startup.

## Hardware and UART

The tested adapter is the XIAO ESP32-S3 carrier with a THVD2410 transceiver.
Use ESP-IDF. The component owns the UART transmitter and tied DE/RE direction.

| Carrier signal | XIAO GPIO | Connection/function |
|---|---|---|
| UART TX | GPIO43 | Transceiver driver input |
| UART RX | GPIO44 | Transceiver receiver output |
| Direction | GPIO4 | Tied DE and /RE; LOW receives, HIGH transmits |
| A / B | RS485 connector | Controller's verified bus pair |
| GND | RS485 connector | Shared signal reference |

These GPIOs describe this carrier, not universal ESP32 wiring. Verify the wall
connector pinout before attaching it. The identification photograph does not
establish RJ12 pin numbering or supply voltage. The damper's 24 VAC specification
does not establish the wall bus supply. See [hardware notes](../hardware/README.md).

## Configure

Use the [complete XIAO example](../../esphome/examples/v1-xiao-all-in-one.yaml)
for the tested carrier, or merge the [V1 fragment](../../esphome/examples/v1.yaml)
into your device YAML. The complete example exposes zones 2–5 and the carrier's
sensors/LED; adjust installed zones and populate `secrets.yaml` from the example.

The essential settings are:

```yaml
uart:
  id: zoneswitch_uart
  tx_pin: GPIO43
  rx_pin: GPIO44
  baud_rate: 250000
  data_bits: 8
  parity: NONE
  stop_bits: 1
  rx_full_threshold: 1

zoneswitch:
  id: zs_bus
  uart_id: zoneswitch_uart
  protocol: v1
  flow_control_pin: GPIO4
  listen_only: true
  enable_polling: false
  status_timeout: 0s
```

Do not also set `uart.flow_control_pin`. Remove previous GPIO4 outputs, UART test
buttons, transmit scripts and TCP bridges so the component exclusively owns TX.
With UART debug enabled use `dummy_receiver: false`. Set `logger.level: DEBUG`
and `zoneswitch.debug: true` when collecting diagnostics.

## Verify reception, then enable controls

In listen-only mode, startup should log V1 and `Listen only: YES`, with `tx_count`
remaining zero. Physical button presses should increment `rx_ok` and update zone
state. Little idle traffic is expected. For example, a status of
`08 00 81 02 03 84 05 17` reports zones 2 and 5 on.

To enable control, set `listen_only: false` and install the updated configuration.
One startup query then occurs. Keep periodic polling off initially. Each absolute
ON/OFF request queries current state, sends a toggle only if needed, then waits
for status. Commands while busy are rejected. Missing replies cancel intent
without a blind retry. UART debug omits the direct-FIFO TX and consumed ACK;
component debug logs the completed handshake.

The default `status_timeout: 0s` means silence alone does not mark the event-driven
bus offline. Use `status_age` to see how old the last observation is. An active
transaction failure marks it offline. See [diagnostics](../configuration.md#optional-diagnostics)
and the [known coexistence issue](../specs/protocols/v1/protocol.md#unresolved-coexistence).
