# Set up a V2.1 wall controller

[Choose another revision](../../README.md#identify-your-wall-controller) ·
[V2 protocol specification](../specs/protocols/v2/protocol.md)

<img src="../assets/v2.1.png" width="320" alt="SMD Version V2.1 printed on the rear of the wall PCB">

Identify the printed **SMD Version V2.1** marking. **V2 is confirmed fully working
on this hardware** and remains the component's default protocol.

## Hardware and UART

Use an ESP32 and a compatible RS485 transceiver. The
[tested installation photographs](../hardware/v2.md) show the original
ESP32-S3-RS485-CAN installation; its GPIOs differ from the XIAO carrier.
Use verified A/B and ground connections and one direction-control owner.
Do not infer another revision's connector pinout from the housing or wire colors.
See [hardware notes](../hardware/README.md).

Merge the [V2 example fragment](../../esphome/examples/v2.yaml) into your device
configuration. Set its TX, RX and direction pins to match your actual adapter.
For the XIAO carrier, these are GPIO43, GPIO44 and GPIO4 respectively:

```yaml
uart:
  id: zoneswitch_uart
  tx_pin: GPIO43
  rx_pin: GPIO44
  baud_rate: 9600
  data_bits: 8
  parity: NONE
  stop_bits: 1
  flow_control_pin: GPIO4

zoneswitch:
  id: zs_bus
  uart_id: zoneswitch_uart
  protocol: v2  # May be omitted; V2 is the default.
  listen_only: true
```

Direction is owned by the UART here; do not repeat the pin under `zoneswitch`.
The fragment enables polling explicitly, so remove that setting or set it false
when using listen-only mode. Remove other UART transmitters and bridges.

## Verify reception, then enable controls

Startup should log V2 and `Listen only: YES`, with `tx_count` remaining zero.
Observe physical button or regular controller traffic. After three matching
status frames the component locks the node address, becomes online and publishes
zone states. `rx_ok` counts valid traffic, including requests; it can increase
before a node is confirmed. Use `node_address` and `online` together.

Set `listen_only: false` to enable control. Polling defaults on every five seconds
unless you explicitly disabled it. The default fallback node is `0x48`; use
`tx_node_addr: 0` to wait for passive discovery on installations with an unknown
address. Zero fallback is not listen-only: once learned, polling/control can transmit.
Only accepted controller state is published. The optional `spill_zone` guard
requires knowledge of the installation; leave it zero if unknown.

Existing V2 YAML remains supported. The
[configuration reference](../configuration.md) covers node learning, persistence,
timeouts, optional diagnostics and entities. The
[validation record](../research/validation/2026-09-17.md) separates confirmed
hardware support from checks of this development refactor.
